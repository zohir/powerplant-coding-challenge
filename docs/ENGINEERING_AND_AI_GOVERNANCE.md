# Engineering Architecture & AI-Supervised Governance

This document explains why this repository includes structured project scaffolding, automation, containerization, and governance artifacts beyond a single Python algorithm script.

---

## 1. Core Philosophy: Agent-First Scaffolding, Human-Reviewed Delivery

In modern software engineering, generating a 100-line dispatch algorithm with an AI assistant is straightforward. The enduring engineering challenge is **how a team structures, constrains, validates, and reviews code** so every line remains simple, maintainable, and production-ready:

1. **Two-Commit Separation (Reusable Stack vs. Domain Logic):**
   - **Commit 1 (`feat: initialize project skeleton...`):** Establishes the company-standard `Python 3.12 + FastAPI + Docker + GitLab CI` baseline (`pyproject.toml`, `Makefile`, `Dockerfile`, `config.py`, `logger.py`, `/health`, `AGENTS.md`, `.gitlab-ci.yml`, `.gitlab/merge_request_templates/Default.md`) completely decoupled from powerplant business logic.
   - **Commit 2 (`feat(solver): implement merit-order productionplan API...`):** Implements the ENGIE challenge domain models, from-scratch merit-order + CO2 + `pmin` back-tracking solver, `POST /productionplan` endpoint, exemplary `pytest` suite, and documentation.
2. **Agent-First & PR-Based Human Governance:**
   - [`AGENTS.md`](../AGENTS.md) defines explicit guardrails for AI coding tools (100–200 line core simplicity budget, zero hardcoded literals, no unrequested business constraints, transparent tested error handling, and human Git ownership).
   - [`.gitlab/merge_request_templates/Default.md`](../.gitlab/merge_request_templates/Default.md) and [`.gitlab-ci.yml`](../.gitlab-ci.yml) enforce that every change passes automated linting (`ruff`) and tests (`pytest`) and can be explained line by line by the human author before merging.

## 2. Key Engineering Principles Implemented

### A. Keep Core Logic Simple (100–200 Lines) & Defend Every Line
- Rather than introducing heavy dependency injection, external optimization libraries (`scipy`/`pulp`), or unnecessary layers, the entire application lives in five focused modules under `src/powerplant/`:
  - `config.py` (~44 lines): Centralized fail-fast environment settings and domain constants.
  - `logger.py` (~34 lines): Standard-library JSON `stdout` logger (`logger.propagate = False`, `exc_info=True` on errors) with zero third-party logging dependencies.
  - `models.py` (~57 lines): `PlantType(StrEnum)` and Pydantic v2 request/response schemas.
  - `solver.py` (~98 lines): From-scratch merit-order + CO2 + `pmin` back-tracking dispatch algorithm.
  - `main.py` (~58 lines): FastAPI `GET /health` and `POST /productionplan` endpoints plus transparent error handlers.

### B. Zero Hardcoded Condition Literals (`Enum` & Centralized Constants)
- Powerplant types are modeled via `PlantType(StrEnum)` (`WINDTURBINE`, `GASFIRED`, `TURBOJET`) in `src/powerplant/models.py`.
- Domain constants live in `src/powerplant/config.py`:
  - `CO2_TONS_PER_MWH = 0.3` (0.3 ton of CO2 emitted per MWh generated by a gas-fired plant).
  - `POWER_UNITS_PER_MW = 10` (integer tenths of a MW for exact `0.1 MW` arithmetic without IEEE-754 floating-point drift).
  - `PERCENT_DIVISOR = 100.0` (wind percentage scaling).
- Runtime environment settings (`APP_HOST`, `APP_PORT`, `LOG_LEVEL`) are validated once at startup via `Settings.from_env()` with zero inline `os.getenv(..., default)` fallbacks scattered in business code.

### C. Business Logic: Merit-Order Economics, CO2 Allowances & `pmin` Back-Tracking
1. **Marginal Cost per MWh (`_marginal_cost`):**
   - **Wind turbines (`windturbine`):** `0.0 EUR/MWh` fuel cost; effective capacity scaled by `round(pmax * wind(%) / 100, 1)`.
   - **Gas-fired plants (`gasfired`):** `(gas_eur_per_mwh / efficiency) + (0.3 * co2_eur_per_ton)` — combines thermal efficiency with European carbon emission allowance costs (`0.3 ton CO2 / MWh`).
   - **Turbojets (`turbojet`):** `kerosine_eur_per_mwh / efficiency` — high marginal cost peak units dispatched last.
2. **`pmin` Step-Down Back-Tracking (`solve_production_plan`):**
   - When remaining load is positive but smaller than the next merit-order plant's `pmin` (e.g., `example_payloads/payload2.json` where `wind=0%`, `gasfiredbig1` takes `460.0 MW`, leaving `20.0 MW < gasfiredbig2.pmin` of `100.0 MW`), the solver steps down already-committed preceding plants in reverse merit order toward their own `pmin` (`gasfiredbig1` stepped down by `80.0 MW` to `380.0 MW`) so the next unit can be committed at `pmin=100.0 MW` (`380.0 + 100.0 = 480.0 MW`).

### D. Transparent, Tested Error Handling
- Real exceptions are never hidden behind generic error strings:
  - `RequestValidationError` (`HTTP 422`): Logs validation details at `WARNING` level and returns exact Pydantic field error diagnostics.
  - `DispatchError` (`HTTP 422`): Raised when fleet `pmin`/`pmax` bounds cannot satisfy `load`; logged with `exc_info=True` and returned with the exact unmet load delta.
  - Unhandled `Exception` (`HTTP 500`): Logged with `exc_info=True` and surfaces `{"detail": str(exc)}`.
- Every handled error class has a dedicated `pytest` test (`tests/test_health.py`, `tests/test_solver.py`, `tests/test_api_payloads.py`).

### E. `Makefile` Developer & CI Parity
- [`Makefile`](../Makefile) provides one-command parity between local development, container testing, and GitLab CI:
  - `make install`, `make lint`, `make test`, `make check`, `make run`, `make clean`, `make docker-build`, `make docker-run`, `make docker-smoke`.

### F. Minimal `Dockerfile` — Line-by-Line Justification

| Instruction | Engineering Rationale |
| :--- | :--- |
| `FROM python:3.12-slim-bookworm` | Stable Debian Bookworm slim image keeping attack surface and image size minimal. |
| `ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 APP_HOST=0.0.0.0 APP_PORT=8888 LOG_LEVEL=INFO` | Avoids `.pyc` files, flushes structured JSON `stdout` logs immediately, and sets required runtime configuration. |
| `ARG APP_UID=1000` / `ARG APP_GID=1000` + `groupadd`/`useradd` | Creates a deterministic non-root runtime user (`appuser`) without hardcoding host UIDs. |
| `WORKDIR /app` + `COPY pyproject.toml ./` + `COPY src/ ./src/` | Copies only build metadata and source package (`tests/`, `.venv/`, `.git/`, `*.md` excluded by `.dockerignore`). |
| `RUN pip install --no-cache-dir .` | Installs the package cleanly without caching wheel archives inside the image layer. |
| `USER appuser` | Enforces non-root container execution at runtime. |
| `EXPOSE 8888` | Exposes the mandatory challenge port `8888`. |
| `HEALTHCHECK ... CMD python -c "import urllib.request; ..."` | Native Python stdlib liveness probe against `http://127.0.0.1:8888/health` (no `curl`/`wget` binary needed in slim image). |
| `CMD ["uvicorn", "powerplant.main:app", "--host", "0.0.0.0", "--port", "8888"]` | Exec-form PID 1 command ensuring graceful `SIGTERM` shutdown. |
